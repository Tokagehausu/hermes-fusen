# v1.1.0 — the four review points from `77dc01b9`

TeKnium's review on PR #153322 asked for four fixes before the entry can be listed.
This is what changed, and where. Nothing else moved: the injection gate, the ops
batch, the REST surface and the desktop half behave as they did.

## 1. The model could confirm its own rewrite

**Was:** `fusen_write` accepted `action="accept"` and `action="discard"`, so the model
could apply its own pending proposal. `revert` always applied, whatever `auto_edit`
said. Because a note is injected into every pinned conversation, one injected turn
could have written text into other chats without the user.

**Now:** the tool's vocabulary is `write` and `revert` only. `accept`/`discard` are
refused with a message naming the two surfaces that can do it (the Desktop panel and
`/fusenapply` / `/fusendismiss`, both new). With `auto_edit` off, `revert` files a
proposal carrying the earlier revision's body (`fusen_tools.py`, `fusen_store.revert_target`).

**Files:** `fusen_tools.py` (`SCHEMA_WRITE`, `fusen_write`), `fusen_store.py`
(`revert_target`), `__init__.py`, `fusen_commands.py`.

**Tests:** `test_the_tool_cannot_settle_its_own_proposal`,
`test_revert_is_a_proposal_when_auto_edit_is_off`,
`test_revert_applies_when_auto_edit_is_on`,
`test_the_user_settles_a_proposal_from_the_keyboard`, `test_dismiss_leaves_the_body_alone`.

## 2. `auto_edit` defaulted to on, against the description

**Now:** the default is off (`fusen_store.DEFAULT_SETTINGS`). The model proposes;
the user applies. `plugin.yaml`, the README, `docs/submission.md` and the panel's
own hint say so in those words.

## 3. Command text was Japanese-only

**Now:** `fusen_i18n.py` holds both bundles. English is the default; Japanese is
picked when Hermes itself is Japanese (`display.language` read through the published
`hermes_cli.config`, then `HERMES_LANGUAGE`). It covers the `/fusen` family's
descriptions and argument hints (`__init__.py`), and every command result and error
(`fusen_commands.py`). `fusen_store.summarize` — the last Japanese string in the store —
is gone; nothing called it. The desktop half keeps its own `en`/`ja` bundles.

**Verified:** `hermes plugins validate .` reports no private-core imports (the first
draft imported `agent.i18n`; that is now `hermes_cli.config`).

## 4. The `HERMES_HOME` fallback and the `plugins-data` typo

**Now:** `plugin_data_dir("fusen")` is the path; the fallback that remains (only for the
dashboard's standalone load, outside the host's package tree) mirrors the helper —
`hermes_constants.get_hermes_home()` and `plugin-data`, spelled as documented. It
resolves to `<hermes home>/plugin-data/fusen` and follows `?profile=`.

**Verified on the dev box:** `data_dir()` → `.../Hermes_Agents/runtime/plugin-data/fusen`.
